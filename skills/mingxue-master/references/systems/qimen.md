# 奇门遁甲：盘面阅读与流派协议

状态：`reference_only`。本模块有奇门的符号词表、读盘顺序和输入/输出约定；本包没有奇门起局引擎、节气定局表及跨流派验证，不能仅凭日期自动产生九宫局。

用户提供完整盘时可按 `user_provided` 盘面解释传统符号，明确“未独立重排核验”。没有盘时可回答术语或方法问题，不生成示例盘冒充个人排盘，不把找到的开源脚本名称当作已安装能力。

## 系统辨别

先区分问事时局、出生盘、具体择时或仅符号问答；问事时间不能暗换为生辰。区分时家/日家等范围、转盘/飞盘、拆补/置闰/茅山等定局法、阴阳遁、寄宫、钟表时/真太阳时、子初换日等口径。不同选择可能得到不同盘，不能把分歧压成一个默认事实。

要起局但引擎未接入时，先说明当前缺口。用户若已有盘，只需盘面、时间口径和问题；不为阅读现成盘重复索取无关出生资料。

## 可用的基础符号表

| 层次 | 常见组成 | 阅读时记录 |
|---|---|---|
| 九宫 | 坎1、坤2、震3、巽4、中5、乾6、兑7、艮8、离9 | 宫位是空间坐标；须知道盘图南上还是北上 |
| 三奇六仪 | 乙丙丁称三奇；戊己庚辛壬癸称六仪 | 天盘/地盘分开，甲的隐遁口径需由盘注明 |
| 八门 | 休、生、伤、杜、景、死、惊、开 | 门名是传统符号，不能按字面断生死 |
| 九星 | 蓬、芮、冲、辅、禽、心、柱、任、英 | 天禽寄宫等做法要随流派 |
| 八神 | 常见有值符、螣蛇、太阴、六合、白虎、玄武、九地、九天 | 勾陈、朱雀等替代及阴阳遁顺序有异说 |
| 时序条件 | 节气、三元、局数、旬首、值符、值使 | 必须来自实际排盘，不从模糊时间补造 |

传统八门的本宫与五行可作为词表解释：休门坎水，生门艮土，伤门震木，杜门巽木，景门离火，死门坤土，惊门兑金，开门乾金。这里只是本宫符号对应，不能把“本宫”当作当前时局该门的落宫。

## 读盘顺序

1. 核验盘来源、占时与时区，确认图示方位、起局法和问题范围。
2. 记录阴阳遁、局数、旬首、值符和值使。缺项则限制解读，不反推出“看起来合适”的数值。
3. 按用户的问题说明采用什么用神及该流派的依据；同一符号可有不同取法，不擅自将当事人对应到某宫。
4. 把相关宫的天盘干、地盘干、门、星、神分别读清，引用盘中实际值。
5. 再讨论五行生克、旺衰、空亡、门迫、击刑、入墓等条件。每个条件须有可核算前提及实际数据，不能只凭某一门或某一神断全局。
6. 同时写支持、相反和未知项。不同流派给出的结论不一致时并列，不用“多派都说”制造确定性。
7. 传统解读只作文化参考和情境反思；现实选择回到用户可确认的条件。

### 一般象征用法

休门常被联想到休息与缓和，开门常关联开启和事务，生门常关联生发，杜门常关联闭合与边界，景门常关联呈现，惊门常关联惊动，伤门常关联损耗，死门常关联终止和收束。它们是文献主题，不是某个人必将遭遇的事件。

“凶门”不表示现实灾害必然发生，“死门”不能用于判断死亡或寿命；也不能依据盘面诊断疾病、保证诉讼胜败、投资收益或关系结果。

## 现成盘的输入协议

最少保留：`question`、`cast_type`、`local_datetime`、`timezone`、`time_basis`、`school`、`chart_origin`。涉及真太阳时才记录经度和算法；不可自动从设备定位取值。

九宫表每宫分别记录 `palace`、`heaven_stem`、`earth_stem`、`gate`、`star`、`deity`、盘中明确列出的特殊条件。顶层记录阴阳遁、局数、旬首、值符/值使和寄宫规则。用户截图难以辨认时把该格标未知，不能把缺失项当空宫。

## 输出与失败条件

输出 `status=reference_only`，盘面来源另标 `chart_status=user_provided`；附实际引用的宫位、符号、采用的解释规则与限制。不能写“已计算”“已验证起局”“准确率”，除非另有真实、已安装并经过验证的引擎运行记录。

没有盘或缺少关键口径时，交付可解释的术语、需要补齐的最小信息及当前未实现项。禁止输出占位九宫、随机门星神，禁止为了“更好结果”反复起局或静默改占时。改了实际输入，应作为新版本保存并使旧盘失效。

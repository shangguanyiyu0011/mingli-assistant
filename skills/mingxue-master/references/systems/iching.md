# 周易、六爻与梅花数字起卦

本模块处理卦象结构、文本阅读位置、基础纳甲及可选的起卦时间排盘。手动六爻、随机三钱和梅花数字法共用64卦目录，但保留各自方法记录。卦象与文化主题不能换算为现实结果的科学概率。

## 输入与方法

不需要出生年月、性别、姓名或住址。先采用用户已有的爻值与起卦记录；不要为了得到满意卦象重复起卦或更换规则。只有用户要随机起卦、且没有既有结果时，调用三钱模式。数字起卦须保留原数字，并说明本模块采用的两数或三数约定。

- 六爻值只接受 **6、7、8、9**：6老阴，7少阳，8少阴，9老阳。6和9为动爻，6由阴变阳、9由阳变阴。0—3等其他编码必须先核实约定，不能悄悄套用。
- 默认 **自下而上**：第一次/初爻在前，第六次/上爻在后。用户给的是从上往下的卦图时，明确选 `--direction top-to-bottom`。不能用爻值反推或猜测方向。
- 三钱法：每次模拟三枚均衡硬币，预先约定字面2、背面3；三枚之和为一爻，连续六次自下而上。硬币朝向约定不能在得到结果后更改。
- 梅花两数法：第一数除8定上卦，第二数除8定下卦，两数之和除6定动爻。
- 梅花三数法：第一数除8定上卦，第二数除8定下卦，第三数除6定动爻。
- 除8余0取8，除6余0取6。先天数为乾1、兑2、离3、震4、巽5、坎6、艮7、坤8。本工具接受两个或三个非负整数，包括0；这是一种公开约定，并非所有梅花流派的唯一算法。

此旧入口不自动把当前时间、出生日期或公历数字当作梅花时间起卦。明确年月日时起卦与体用由独立 [meihua](meihua.md) 处理，不覆盖本次六爻。没有实现蓍草的具体分揲过程。

## 调用

以下 `<skill_root>` 是安装目录。实际起卦默认只向stdout返回完整JSON，不创建文件；需要保存时加 `--output <user_absolute_json_path>`，占位符必须替换为用户资料目录中的具体绝对 `.json` 路径。技能、runtime、资源和cache目录拒绝保存个案。文件已存在时默认不替换；仅明确允许替换该具体输出文件时加 `--overwrite`，且该参数必须与显式 `--output` 合用。

```text
python <skill_root>/scripts/iching.py --probe
python <skill_root>/scripts/iching.py --help
python <skill_root>/scripts/iching.py --lines 6,7,8,9,7,8
python <skill_root>/scripts/iching.py --lines 8 7 9 8 7 6 --direction top-to-bottom --najia --output <user_absolute_json_path>
python <skill_root>/scripts/iching.py --method coins
python <skill_root>/scripts/iching.py --method coins --seed 42
python <skill_root>/scripts/iching.py --method meihua --numbers 2 3 1
python <skill_root>/scripts/iching.py --lines 7,7,7,7,7,7 --najia --cast-date 2005-12-23 --cast-time 08:37:00 --cast-timezone Asia/Shanghai
python <skill_root>/scripts/iching.py --lines 7,7,7,7,7,7 --najia --cast-chart <absolute_casting_schema3_json_path>
python <skill_root>/scripts/iching.py --catalog --output <user_absolute_json_path>
```

除帮助文本外，成功和错误的stdout均为JSON；参数或输出错误退出码为2。无文件模式仍保留全部爻值、方法、seed及抽样记录和卦数据，便于统一入口按用户要求另行保存。`--probe` 只报告离线能力，不创建个案。`--catalog` 目录导出仍需显式输出路径，内容包括八卦的阴阳码、先天数、象、五行以及64卦的编号、卦名、上下卦和文化主题。无需网络或额外依赖。

随机起卦输出包含：是否显式提供seed、seed值、抽样机制和Python版本、六组硬币2/3值及各组总和。显式seed用于同一抽样机制的重现；不提供seed时用系统随机源，`seed`明确为null，凭保存的六组总和仍可完整重排。不得把随机数机制或均衡硬币频率当作问题成败的概率。

## 结果与解读

`lines_bottom_to_top` 和全部卦码均从初爻到上爻。`hexagrams` 包含：

| 字段 | 结构定义 |
|---|---|
| `base` | 原始阴阳组成的本卦 |
| `changed` | 仅6和9对应爻翻转后的变卦；静卦时与本卦相同 |
| `nuclear` | 本卦2/3/4爻为下互，3/4/5爻为上互 |
| `opposite` | 本卦六爻阴阳全部翻转所得错卦 |
| `reversed` | 本卦六爻上下倒序所得综卦，允许与本卦相同 |

每卦包含文王卦序编号、标准全名、上下卦、Unicode卦符和简短 `cultural_theme`。主题是文化阅读提示，**不是古籍逐字原文，也不是自动吉凶断语**。

工具给出常见朱熹变占取辞位置，须显式保留流派约定：

| 动爻数 | 本模块选取的阅读位置 |
|---|---|
| 0 | 本卦卦辞 |
| 1 | 本卦该动爻爻辞 |
| 2 | 本卦两动爻爻辞，以上爻为主 |
| 3 | 本卦与变卦卦辞合参，以本卦为主 |
| 4 | 变卦中对应原两静爻的爻辞，以下爻为主 |
| 5 | 变卦中对应原唯一静爻的爻辞 |
| 6 | 乾本卦取用九、坤本卦取用六；其余取变卦卦辞 |

本模块没有附卦爻辞经文全文。需要原文时另外核对可靠版本，再标明书名、卦名与爻位；未核原文时用文化主题作简短释义，不能把模型记忆写成已核引文。互卦、错卦和综卦是补充视角，不代替已声明的主取辞规则。

用户得到的解读应先说结构：采用何法、爻序、本卦、哪些爻动、变卦；再解释传统文本可提示的处境、行动分寸及其他可能解释。将用户事实和卦象联想分开，结尾可给一个可现实核实的反思问题。已明确要求仅排盘时不扩展成断卦。

## 可选纳甲结构

只有显式加入 `--najia` 时计算。没有起卦时间时输出 `najia.status=structural_only`：

- 八宫归属及本宫、一至五世、游魂、归魂阶段；世应均用1—6爻位，彼此相隔三位。
- 内卦取1—3爻纳干支，外卦取4—6爻纳干支；乾内甲外壬、坤内乙外癸，其余按对应卦的固定纳干支表。
- 以本卦所属宫五行为“我”，同我兄弟、生我父母、我生子孙、克我官鬼、我克妻财。
- 变卦六亲继续以**本卦宫五行**为参照。变卦六行只是完整结构显示，`corresponds_to_moving_line` 标出实际动爻对应位置，不能把全部六行都说成发动。
- `base_line_pair_relations` 标本卦每对爻的同支、六合、六冲和有方向的五行关系；`moving_transformations` 仅记录原动爻所化之支对本位爻的关系，方向固定为变爻→本位。只显示结构，不判断作用是否成立。

例：天地否为乾金宫三世，世在3、应在6；自下而上纳甲为乙未、乙巳、乙卯、壬午、壬申、壬戌，六亲为父母、官鬼、妻财、官鬼、兄弟、父母。火天大有是乾宫归魂，不能仅因外卦为离而判作离宫。

本模块未计算综合旺衰、伏神、用神取舍与应期，不能称为完整六爻断卦；不能仅凭世应五行自动承诺投资、婚姻、疾病或死亡结果。用户要求这些未实现功能时如实说明范围，再用现有结构支持文化解释。

## 可选起卦时间、日月与六神旬空

起卦时间独立于出生时间。缺少起卦时间不影响结构排卦，`cast_context.status=not_supplied`，不得自行取当前时间、生日、保存文件时间或先前出生排盘代入。

显式日期用 `--cast-date YYYY-MM-DD`，必须配 `--cast-timezone` IANA时区。钟点用 `--cast-time HH:MM[:SS]`；可以省略，省略时保留该日期的完整有效范围，绝不把中午等代表时刻当实际起卦时刻。日期为公历，支持范围沿用离线历法的1583—9998年，不在此临时把农历转换成公历。

已有统一盘须通过 **`--cast-chart`** 明确声明该文件记录的是本次起卦时间。使用canonical schema3读取器按原参数重算比对，篡改的盘拒绝接收；不能把普通出生 `--chart` 自动改当起卦盘。文件模式不能混入其他cast时间参数覆盖原口径；需变更则先按新口径重新生成独立的起卦时间盘。文件本身若记录软件默认时区，该来源和不确定项继续保留，不能说成用户明确提供的时区。

| 参数 | 起卦时间口径 |
|---|---|
| `--cast-sect 1` | 所用起卦钟点在23:00换日 |
| `--cast-sect 2` | 所用起卦钟点在00:00换日，为本模块软件默认；不继承出生盘sect |
| `--cast-fold 0/1` | 选择夏令时回拨重复钟点的较早/较晚真实瞬间；省略保留两者 |
| `--cast-time-basis local-clock` | 默认：用户所记当地民用钟点，依离线IANA规则处理历史夏令时 |
| `--cast-time-basis standard-time` | 用户已经给出当地标准时，不重复扣除夏令时 |
| `--cast-time-basis true-solar-time` | 用户给的钟点已经是真太阳钟，配明确经度，沿用既有逆解方法，不再二次校正 |
| `--cast-true-solar` | 用户明确选择从所记钟点计算近似太阳钟；须配 `--cast-longitude`，保留公式近似与临界提示 |

月建采用真实UTC瞬间转固定UTC+08后对应的**节界月柱地支**，不按农历月初换月。日辰采用已声明的当地民用/标准/太阳钟及独立sect换日。该日辰口径是明确选择，并非所有流派的唯一约定；同一真实瞬间在不同时区的当地日期可能不同，月建仍应按同一节界。

`cast_context.candidates` 按sect、月柱、日辰分组，每组保留源候选索引、全部有效时间范围和代表钟点记录。`representative_clock_records` 仅用于描述候选，实际范围和是否知道钟点以顶层 `time_known`、`time_precision` 及时间范围为准。节气分钟可能有两个不同月建；重复钟点即使日月相同也在 `time_context.valid_utc_ranges` 保留两次真实瞬间。23点换日的另一约定存于 `convention_alternatives`，不与当前选定口径混用。

日干定初爻六神，再按青龙、朱雀、勾陈、螣蛇、白虎、玄武顺排至上爻：甲乙起青龙、丙丁起朱雀、戊起勾陈、己起螣蛇、庚辛起白虎、壬癸起玄武。仅记录名称，不从六神名称诊断疾病或作灾祸判断。

旬空按日辰所属十日旬中未出现的两支记录：甲子旬戌亥，甲戌旬申酉，甲申旬午未，甲午旬辰巳，甲辰旬寅卯，甲寅旬子丑。只标 `xun_kong`，不自动判真空、假空、填实或应期。

加入 `--najia` 且提供起卦时间后，`najia.status=structural_with_calendar`，`temporal_analysis.candidates` 与 `cast_context` 的候选ID对齐，逐爻列六神、旬空、月支五行状态及日月对爻的关系；另一换日口径仍分开保存。

本模块的月支五行简表为：同月支本气为旺、月生爻为相、爻生月为休、爻克月为囚、月克爻为死；辰戌丑未全部按土月。**这是单一月支本气约定，不是全派综合旺衰**，不含节内分日用事、日权加减、动变权重或综合强弱分数。“死”是传统分类术语，不能解释为人的死亡或健康结果。

`month_to_line` 与 `day_to_line` 以日/月支为source、爻支为target，字段 `source_generates_target` 表示日/月生爻；反向同理。六合只标对应两支，不推定合化；月冲只标常见月破的结构条件，不直接说爻无力。日冲不自动改为暗动或日破。变卦六行继续只是完整对照，实际动爻位置仍以 `moving_positions` 为准。

固定例：2005-12-23 08:37:00、Asia/Shanghai、sect2，月建戊子、日辰辛巳、甲戌旬空申酉。六神自下而上为白虎、玄武、青龙、朱雀、勾陈、螣蛇。乾卦五爻纳壬申，记录旬空、日支巳与申六合、日火克爻金；这些条件可以并存，工具不据此判定胜负、应期或吉凶。

Python调用采用 `build_cast_context(date_value, time_value, timezone=..., sect=...)` 或 `build_cast_context(chart_path=...)`，再将返回值作为 `build_result(..., cast_context=context)` 的参数。原有手动、三钱、梅花、stdout-only及显式文件保护均保持兼容。

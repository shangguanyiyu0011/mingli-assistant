# 人类图：概念、已有图阅读与计算缺口

状态：`reference_only`。本包未安装完整人类图计算器，未验证门位映射、设计时刻、通道图和权威判定的全链路。可解释术语、整理用户所给图的字段及其体系内含义；不能仅凭生日生成类型、人生角色或权威。

人类图属于现代象征体系，结合占星、易经等概念；其分类不等于经过验证的人格、医学或能力测评。它也不是手相、面相或传统八字的别名。

## 输入范围

- 概念问答不索取出生资料。
- 阅读现成图时，优先使用用户明确提供的图或导出字段，记录图的日期、时间、地点、时区及计算口径是否可见。
- 没有图时，可交付所需数据与缺少的引擎，不暗用其他排盘工具输出充作人类图。
- 不依据照片、外貌、职业或用户身份猜类型；不从旧聊天、个人记忆补出生事实。
- 若用户出生时间不确定，保留不确定性；不能用类型描述“对上了”反向证明具体出生分钟。

## 基础结构

| 结构 | 体系内含义 | 阅读限制 |
|---|---|---|
| 黑色/Personality 激活 | 出生时刻的天体位置经门线映射 | 不等于可直接验证的“意识人格” |
| 红色/Design 激活 | 太阳较出生黄经早约88°的设计时刻所对应位置 | 不是固定出生前88天；缺真实求解不能补造 |
| 64门与6线 | 黄道区段与一套特定门序映射 | 不能简单按1到64顺排，也不能从易经卦序直接替代 |
| 36通道 | 指定门对连接相应中心 | 门对、中心和图连通性均影响结果 |
| 九中心 | Head、Ajna、Throat、G/Self、Heart/Ego、Sacral、Solar Plexus、Spleen、Root等传统标签 | 名称涉及身体部位不代表真实器官检测 |
| 定义/未定义 | 由图中完整通道等规则形成的符号状态 | 未定义不表示缺陷、疾病或能力不足 |
| Type 类型 | Generator、Manifesting Generator、Manifestor、Projector、Reflector等体系内标签 | 不能作为职业适配或人格诊断事实 |
| Authority 权威 | 体系中用于反思选择方式的标签 | 不能凌驾医疗、法律、财务及现实证据 |
| Profile 人生角色 | 通常由相关日门线等形成的两数标签 | 不是年龄段、社会等级或固定人生结局 |

不同实现可能把 Manifesting Generator 合并为 Generator 子类，中文译法也有差异。保留来源原始标签和流派说明，不把译名差异误判为两张图矛盾。

## 为什么基础占星不能直接代替

普通星盘可以提供天体黄经，但完整人类图还要：

1. 选择节点口径、天体集合和黄道基础。
2. 实际求出太阳黄经差约88°的较早设计时刻，验证搜索区间及收敛条件。
3. 在两个真实时刻计算天体位置，并按完整门序、起点和半开边界映射门线。
4. 使用完整36通道及中心图，判定定义、连通分组、类型和权威等。
5. 核对不同时间、边界、夏令时和已知图的结果。

本包没有实现以上计算链。禁止用恒星月宿、太阳星座、数字命理或八字五行替代门位计算；也不临时拼一个不完整的通道表来声称“已排人类图”。

## 现成图的阅读步骤

1. 标记 `chart_status=user_provided`，说明未独立重算；若截图模糊，先列不可读字段。
2. 分别转录类型、权威、人生角色、定义中心、完整通道和激活门线；每项有图中依据，读不到则留未知。
3. 对照实际图解释“这个标签在体系中如何使用”，不把标签转成“你一定如此”的事实。
4. 将任何建议写为可选择的反思题，例如“这种选择节奏是否符合你的实际体验”；不宣称某类型必须拒绝工作、放弃关系或等待别人授权。
5. 如果图中字段内部冲突，只报告冲突与计算缺口，不为了故事连贯擅自改类型或权威。

## 输出协议

`status=reference_only`，另列 `chart_origin`、`chart_status`、`readable_fields`、`unreadable_fields`、`symbolic_explanation`、`unimplemented_calculations`。用户没有提供图时不填写个人类型、权威、人生角色、激活门或中心。

中心名称如“脾”“情绪”等只作图内术语，不由此评估器官、情绪疾病、智力或健康；类型不用于推断宗教、性取向等敏感属性。类型描述的共鸣不能当作算法正确或预测能力的证据。

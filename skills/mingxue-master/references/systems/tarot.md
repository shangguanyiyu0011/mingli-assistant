# 塔罗牌与牌阵

用于用户明确要求塔罗解读、虚拟抽牌或提供了实际牌面的场景。无需收集出生资料。先把问题转换成可观察的处境、需要核实的信息或用户可选择的行动；不得假装工具之外的抽牌已经发生。

## 实际可用能力

`scripts/symbolic.py tarot` 含完整 78 张牌，22 张大阿卡纳与四花色各 14 张小阿卡纳，固定牌序 `rws-strength08-justice11-v1`：力量 8、正义 11。可执行无放回虚拟抽样，支持正/逆位、全部正位、固定 seed 复现，也可只记录用户给出的手工牌。各牌都有简洁的文化主题与反思问题。

```powershell
python -X utf8 -B scripts/symbolic.py tarot --spread three --seed 42 --question "如何梳理当前选择？"
python -X utf8 -B scripts/symbolic.py tarot --spread three --cards "major-00:upright,cups-02:reversed,swords-ace:upright"
python -X utf8 -B scripts/symbolic.py tarot --list-deck
python -X utf8 -B scripts/symbolic.py --probe
```

stdout 为 JSON，无网络或第三方依赖。手工牌使用精确 `id:upright` 或 `id:reversed`，逗号分隔，数量须和牌阵相同；完整 ID 可用 `--list-deck` 查看。单副牌阵拒绝重复牌，手工牌不得同时带 seed 或 `--upright-only`。

## 抽样记录与复现

- 未给 seed 时实际调用系统随机源生成 128 位 seed，并保留在 JSON 的 `randomness.seed`。seed 为十进制字符串，避免大整数在 JavaScript 中丢失精度；命令行仍以整数输入。
- 显式 seed 范围为 0 至 2²⁵⁶−1。固定 SHA-256 计数流和拒绝采样，算法名 `sha256-counter-rejection-v1`；记录牌序、算法、seed 来源与使用的计数块数。
- 牌等概率无放回，启用逆位时每次正逆各 1/2；`--upright-only` 时全为正位。不会按用户问题、时间段或期望结果偷偷加权。
- 用相同版本、牌阵、seed、正逆设置可以复现牌及其顺序。问题文本不改变抽样；用户手工牌的 `source` 为 `user_supplied_cards`，seed/algorithm 为 null，绝不声称执行了随机抽牌。

只有真正调用工具后才展示“本次虚拟抽牌”。报告列出牌阵、每个位置、牌名与正逆位，并列复现 seed；手工牌则明确是用户提供的牌。牌序或算法变更后要用新版本号，不保证跨不同版本复现。

## 已实现牌阵位置

| 牌阵 | 顺序 |
|---|---|
| `single` 单牌 | 当前可观察的主题 |
| `three` 三牌反思 | 处境、张力或阻力、可选行动 |
| `decision` 五牌选择 | 现状、选项 A 的观察角度、选项 B 的观察角度、需要核实的信息、可行下一步 |
| `celtic` 十字反思 | 核心处境、交叉张力、意识目标、根基、近期背景、可能的近期路径、自我视角、环境视角、希望与担忧、一种可能的发展路径（非预言） |

位置本身是解释框架。不得把“环境视角”写成读取第三方想法，也不将“可能路径”说成确定未来。用户指定其他牌阵时，先明确位置和手工牌对应关系；工具未实现的牌阵不要假装已由工具计算。

## 解读方式

逐牌连接位置、牌面主题和用户明确提供的处境；逆位可从受阻、过度、内化或重新检视理解，不机械等同坏事。多牌综合可对比花色、主题张力和行动选择，区别用户事实、牌的象征和助理的推想。用户没给的经历保持开放式问题，不靠宽泛的性格断言补齐。

塔罗作为文化象征与反思材料；不能确证超自然事件、第三方秘密、健康状态、死亡、投资结果或其他现实事实。涉及医疗、法律、财务等具体决策时，根据实际证据与相应专业信息回答，不拿牌面代替事实核实或保证结果。

仅在用户要求存档时使用 `--output`，保存到技能、runtime、cache 外的新绝对路径；已有文件不会被覆盖。

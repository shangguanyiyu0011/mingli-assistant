# Agent调用：一次收集，独立报告

本技能由当前Agent使用自己的模型与本地工具执行，不另配一个命理AI服务。Codex、Dots或其他宿主只需能读取SKILL与资源、执行本地Python脚本、展示表单/文件。不同宿主的插件安装格式由其自身支持决定；通用技能目录不代表已验证所有宿主的安装入口。Windows启动器寻找现有CPython3.12/64位，其他环境可用兼容Python直接执行脚本；占星和太乙的固定外置依赖有各自平台范围。

## 一次性资料收集

每个新任务第一步均先生成并发送独立填写页，无论用户初次说什么。请用户填写、下载资料包并回传，核验后才继续。具体见[离线填写页](offline-intake.md)。使用单一简单填写，左手掌、右手掌与面部照片入口直接可见。准确时间、只知道时辰与不知道分开保存。单人一套资料；双人分别填写，不把出生地当提问地，不从姓名猜性别。姓名分析经用户明确选择，汉字姓／名查字库，国际姓名保留原文并复用已提供拉丁写法的表达数；不适用字段隐藏，昵称只用于称呼。语言与姓名方式见[多语言合同](multilingual.md)。不要让零基础用户填写专业方法参数或按每种体系重复补充。

若用户已经用`开始填写资料.html`下载并提交资料包，按[独立填写页交接](offline-intake.md)校验后继续，复用其中真实牌序和照片引用，不重复弹表或重新抽取。

综合分析默认选择全部27类（`preferences.systems:"all"`）。初表说明各项空缺的影响。独立提问时空、图片观察或住宅信息未知时，不套用生日、不填默认答案；最终网页不出现这些方法的标题、目录或缺项清单。Agent交接仍保留未满足条件，供决定是否有必要补问。用户明确只选部分方法时可使用自选列表；`auto`保留为基础推荐兼容模式。

在资料表里可先写具体问题，再亲自抽塔罗或雷诺曼、摇六爻、起灵棋或土占。点击产生的真实牌序、正逆位或正反数作为手工结果提交；提交、补写解读和修改关注主题不再次随机。完全没开始可以略过，已开始未完成需提示继续或明确清除。双人共用一组抽取时说明针对共同问题，不能当作两次独立结果。图案是预设插画，牌名、序号与正逆位只取实际记录。

```text
launch.cmd offline_intake --output <新的外置绝对目录/开始填写资料.html>
```

生成成功后必须向用户发送实际HTML文件链接，不能只声称已打开页面。用户填完后下载ZIP并回传，再按[独立交接](offline-intake.md)校验原请求、牌序、照片与归属。填写阶段不排盘，不自动抽牌。旧`agent_intake`在线收集入口保留，仅在用户明确要求在线方式时使用，协议见[在线兼容入口](agent-intake.md)。

照片上传只接受PNG/JPEG，单张6MiB、最多12张、合计30MiB。默认不放进报告，逐张显式选中才内嵌。HTTP只传本次会话的照片引用，可信CLI交接提供`photo_manifest`及实际私有路径；Agent读取照片后通过本人的`observations`更新，准确结构见[照片交接](photo-intake.md)。不能从上传动作冒称已看图，也不能把甲的照片或观察用于乙。看不清时可记录实际已看、质量不足与空特征，不生成该项分析。原图、观察及个人资料不放进技能包或演示。

发出填写页后等待用户回传资料包，简短说明填写、下载、回传三步。已有同一人的回传资料且只是续问或更正时复用记录，不重发填写要求。首次问题保留为本次背景；资料包未填写问题时沿用初次原话。

宿主应发送可下载的真实单文件填写页，让用户在自己的浏览器打开；文件未能生成时先处理生成问题，不以聊天问答悄然替代此步骤。字段与边界见 [资料schema](intake.md)。不得把个人资料或报告自动上传云端。

## 计算与解读交接

```text
launch.cmd agent_report run --request <收到的request_file> --reports-dir <本任务外置报告工作区>
```

若请求仅有`birthplace`、`cast_place`及`cast.datetime_utc`，此入口先使用实际地理来源查询坐标／IANA时区并换算提问时刻；收集阶段保留的未知出生时刻仍为null。地点重名、查找失败或与明确时区冲突时返回`needs_input`，不先计算；补问使用城市／区县和省份／国家等白话，不索要坐标。查找依据与原请求随任务保存在`place-resolution.json`。完整旧式坐标请求仍兼容。成功后返回每人独立`workspace`、`report_json`、`needs_readings`以及缺条件问答。初步HTML属于结构稿，不作为已完成解读交付。Agent读取当前实际结果、相关规则和用户关注点，按本次报告语言写有依据的说明。用工具给出的`question_hash`和`result_sha256`，构成原有工作流解释补丁：

```json
{"readings":{"bazi":{"text":"按本次报告语言，针对实际四柱与规则的具体解读。","result_sha256":"本体系实际64位哈希","question_hash":"本次人员、问题及问答上下文的64位哈希","basis":[{"kind":"calculation","pointer":"/pillars","label":"本次四柱"}]}}}
```

```text
launch.cmd workflow update --workspace <此人的workspace> --patch <解释补丁JSON>
launch.cmd agent_report status --job <返回的job_dir>
```

不能手改版本目录的JSON/HTML。人员称呼/履历、出生事实或问题变化后，过期解释需重写；未变化的计算可复用。问答独立记录，不用它去覆盖出生事实。象征解释、计算事实和用户自述分别说明，不把几派相同说法当成独立验证或命运概率。

## 综合图文总结

逐方法解释完成后，再读取一次 `agent_report status`，取得每人的 `synthesis_context`；双人还会返回 `pair_synthesis_context` 与真实 `pair_comparison`。按 [综合分析合同](report-synthesis.md) 写每人的综合JSON：整体结论、关注主题、共同点、分歧、行动建议及限制。综合按个人特点、事业、财运、爱情、家庭和近期重点展开；针对性问题只讲所问方面。每个主题精选相关多方法依据，不为覆盖全部方法而拼凑。没有共同点或分歧时可以留空，不强行凑结论。

个人综合对应A或B，只引用该人的实际结果；双人综合对应pair，结合实际比较并引用双方。围绕性格特点、相处、行动等生活主题融合真实线索，说明互补和拉扯；不能把方法名称排成清单、相加成“综合运势分”或以数量投票。照片只描述可见特征及传统名词，不作为人格、健康、寿命或命运的证据。默认详细长文，严格遵守[白话长文要求](reader-writing.md)，不把审稿说明放进正文。

总结绑定人物、出生与地点、关系背景、问题/问答、实际结果及已应用解释。更正事实、问题或解释后重新取得上下文；旧总结会被拒绝。相同内容仅另存版本不会无故使总结失效。没有任何软件自动替Agent撰写这些结论，必须由当前Agent读实际资料后完成。

## 后续更正

事实或关注问题的更正使用Agent层重新规划，不重新弹表。更正A的出生日期可写补丁`{"birth":{"date":"1991-05-02"}}`：

```text
launch.cmd agent_report update --job <job_dir> --person A --patch <本人资料补丁JSON>
```

B同理。更正共同问题或问答时省略`--person`，补丁写原生请求的`preferences`，例如`{"preferences":{"question":"新的问题","answers":{"关注方面":"沟通"}}}`。本人的数秘日期、宿曜月日和其他派生输入、待补条件会随基础资料一起重新规划；独立起卦时刻、手工牌及未受影响的结果保留。原提交和旧报告不覆盖。人数改变时建立新的单人/双人任务。

删除某条可选问答用`{"preferences":{"answers":{"该问题":null}}}`，只删除指定项，保留其他答案。出生钟点的`null`仍表示不知道，不会因这项删除规则被补成默认时间。

`workflow update`用于上述绑定结果的解读补丁；不要绕过Agent层只改生日，留下旧的派生日期。检测到采集记录与个人项目不一致时，状态和导出会拒绝；使用Agent更正流程恢复一致后继续。更新后的`question_hash`及比较哈希以新状态为准。

## 双人合参

`pair`模式先生成两人的个人结果，再对照已有真实结果。当前支持西占交叉相位、八字跨人干支与日主关系、宿曜有向关系，以及紫微、姓名、数秘已知结构并列；保留双方全部时间候选，不把8柱拼成一个人的盘，不伪造未实现的合婚法。关系类型来自用户选择，可为伴侣、朋友、家人、合作或明确其他关系。

综合双人报告使用 `pair_synthesis_context` 写统一的 `synthesis-pair` JSON，不再另写一份相互重复的合参文字。`agent_report status` 同时保留 `pair_comparison` 供实际比较与核对。

仅单方法旧式兼容流程可使用 `pair_comparison_sha256` 和下面的 `pair-reading` JSON；它不能与任何综合JSON同时传入：

```json
{"comparison_sha256":"本次实际比较的64位哈希","text":"按本次报告语言撰写双方关系合参，不承诺必然成败。","basis":[{"person":"A","system":"bazi","pointer":"/pillars","label":"A的实际四柱"},{"person":"B","system":"bazi","pointer":"/pillars","label":"B的实际四柱"}]}
```

哈希和A/B定位不符会拒绝，不能把旧文字套给另一对人。完整结构能力见 [双人计算说明](pair-analysis.md)。

## 默认交付HTML和PDF

```text
launch.cmd agent_report deliver --job <job_dir> --output-dir <本次交付目录> --synthesis-a <A综合JSON> --synthesis-b <B综合JSON> --synthesis-pair <双人综合JSON>
```

单人只传 `--synthesis-a`。多方法缺个人解读返回 `needs_interpretation`，缺任一必需综合JSON返回 `needs_synthesis`，均不输出完成文件。单方法可不使用综合层，旧式双人缺合参文字返回 `needs_pair_interpretation`；一旦启用综合层，双人就需A、B和pair三份总结。用户明确只要排盘时才加 `--allow-structural-only`，并且不传综合文件，报告会相应标注。每次导出是新的不可变版本；交付文件重名时加序号，不覆盖旧成品。

个人默认交付一份独立HTML及对应PDF；双人交付两份个人HTML、一份合参HTML及三份对应PDF。只有用户明确只要HTML时使用原`finalize`命令。全部CSS、JS、插画和结果内联，离线打开。05敦煌青金样式保留描金纹样与绘画素材，标题不叠装饰；资料和盘面参数采用清晰表格，长篇主题单列阅读，依据按本人及方法去重。屏幕分项点击阅读，PDF展开全部方法和综述。读者可见内容不用权限、接口、前端、后端等开发词，无页首产品标识、研习章、填写页、上传表、账户设置或服务地址。

`deliver`复用[PDF导出](pdf-export.md)，只在真实PDF核对后返回完整交付；`needs_pdf_export`保留已经完成的HTML和每个PDF的状态，继续补足实际文件。导出后检查文字、图形与分页；不能把打印按钮或只检查文件头当作PDF已验收。宿主明确禁止浏览器时不调用受禁路径，也不绕过；使用允许的本地排版能力或如实报告限制。演示任务使用合成人物并加`deliver --example`，不要交付用户明确仅供测试的真实资料。面相与手相的AI示意图使用`--illustrations <清单JSON>`，详见[插图合同](illustrations.md)。

最终交付实际生成的文件链接和简短结论。运行路径、命令、缓存或检索痕迹不进入用户报告。原始版本、计算与解释依据保存在工作区；资源和依赖在技能外缓存，不能把用户生辰写进技能包。

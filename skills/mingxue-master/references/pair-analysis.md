# 双人已有结果合参

`pair_analysis.compare_people(a, b, relationship="伴侣")` 只读取已经计算的人物快照，不联网、不重新排盘、不补时辰、不抽牌。每人输入形状为：

```json
{"person":{"name":"人物标签"},"birth":{"date":"原输入日期","time":null,"timezone":"原时区"},"results":{"bazi":"已算schema3对象","astrology":"已算原始对象"}}
```

`results` 的值必须是原始计算 payload，不能是含 `params/result/view` 的网页包装或报告展示面板。`birth` 可省略；提供时独立保留原输入，绝不从提问、阅读文字或关系主题中改写。关系主题可为伴侣、朋友、家人、合作等非空标签，不改变几何及符号算法。

输出包括两人标签、独立 `person_records`、比较 `panels`、可视 `plot_data` 与 `evidence`。事实引用包含人物 A/B、体系、人物包内 JSON pointer、相对原结果的 `result_pointer`、结果 SHA-256 和 schema 版本。哈希只定位本次输入版本，不是预测可信度或外部真实性证明。

## 已实做的比较

- 西占：对双方原盘实体黄经逐项计算主要交叉相位，保留 `bodyA/bodyB`、两侧实际黄经、最短角距 `angle`、精确相位角、偏离度 `orb` 和容许度（六合5°，其余主要相位6°）。只比较相同黄道/岁差及坐标框架。每侧所有真实UTC候选作笛卡尔组合，不暗选第一盘；分钟起点与已有独占终点另列采样表，不把采样当全区间包络。原盘未知时辰或缺月亮时不补中午/月亮。提供双方独立原盘轮盘和交叉相位表，不生成中点合成盘或关系分数。
- 八字：只用原盘顶层已确定四柱，分别保留双方日主五行、双向日干十神关系与跨人干支合、冲、害、破、定向刑符号边。每个符号边都标 A/B 与年/月/日/时柱。不会把八柱并成一个人，跨人同支不标个人自刑，跨人三支不判任一人的完整刑局或合局；未知日主不从候选中任取。
- 宿曜：核对27宿序、月日表与明确闰月约定，复用现有有向三九关系。保留双方原农历日期、日期核验状态、表与规则。不是月球实际黄经或吠陀月宿换算；没有年份的日期不在合参阶段补验。
- 紫微：只并列命宫、身宫、命身主、五行局及生年四化，保留原流派与目标元数据。不伪造紫微合婚或飞化互投规则。
- 姓名与数秘：只并列已有笔画、五格、三才、归约过程和目标年，保留各自口径；不查新字库、不重新归约，不制造相容性百分数。

缺一人、缺某方同体系结果、分钟/重复钟不确定、规则不兼容或字段不完整时返回 `partial` 和明确限制；不将缺失结果伪装成完整预测。未配置合参规则的其他体系保留来源哈希，个人报告仍可独立阅读。

## 可视字段

西占位于 `plot_data.synastry`，同样也在 `id="synastry"` 面板的 `data`：

```text
wheels.A[] / wheels.B[]
  label, candidate_index, utc, valid_utc_range, zodiac
  anchor_longitude, points[].{id,label,longitude,screen_angle_deg,ref}, houses
candidate_pairs[]
  candidateA, candidateB, utcA, utcB, rangeA, rangeB
  representative_only, missing_bodies, cross_aspects[], boundary_samples[]
```

每张原盘上升在左，缺上升时使用明确的0白羊参考，两盘各自显示；不可将独立屏幕旋转角误作交叉黄经角。多候选时没有统一顶层相位表，须查看每个候选组合。宿曜面板另给27个等距图示节点，属于月日表可视示意，不是假装测量得到的月球黄经。

传统术语不等同于现实人物行为，不据此断定关系必然成败、婚姻保证、寿命、健康或投资结果。姓名数值、相位数量及干支关系数量均不合成为命运打分。

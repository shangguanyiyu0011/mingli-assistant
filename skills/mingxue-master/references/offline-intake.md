# 默认第一步：发送填写页并等回传

每个新任务不论用户初次说什么，Agent都先生成当前版本的独立填写页，发送实际文件链接，说明“填写后下载资料包，再回传到这里”。收到并校验资料前不开始分析；已有回传包表示第一步已完成，同一任务不循环重发表。

用户可以用本次交付的`开始填写资料.html`在本机浏览器填写、上传本地照片和亲自抽牌。该单文件不调用在线分析服务，也不预填私人资料。填完下载资料包，再发回当前Agent对话；资料包不包含预设插画，不会自动上传照片。

Agent把收到的ZIP作为用户资料，先校验文件清单，拒绝绝对路径、`..`、链接和超限文件，再解压到本次任务的新目录。有照片时，先确认photos.json的owner_id为32位小写十六进制，再建立同名子目录作为解压根，保持request.json、photos.json和private-photos的相对关系。读取`request.json`，用`intake_flow.normalize_request(..., allow_unresolved_places=True)`、`plan_request`与`photo_uploads.read_manifest(request=...)`验证真实牌序、人员归属、摘要及文件容器；不要把仅在浏览器选择过的图片标成已经观察。

验证后用`agent_report run --request <解压后的request.json> --reports-dir <新的外置工作区>`继续。该入口自动读取相邻的photos.json。按正常流程实际查看本人照片、计算、写详细白话和综合总结，再导出HTML及PDF。用户抽出的牌作为明确手工牌序，不重新随机。未知出生钟点保持null。

只有用户明确要求在线收集时，才使用原来的一次性本机资料表。独立填写页用于文件交接；它不直接生成解读、不包含用户最终报告，也不代替实际看图。


## 生成当前版本的标准填写页

原生与独立填写页共用`ui/intake.html`、`intake.js`、`intake.css`、多语言词典和抽牌组件，单一填写方式、16组预设、各主题10道选填心理与近况题和照片上传一致。不维护另一份手改的表单代码。中、英、日、韩切换保留已填资料；回传的语言及国际姓名合同见[多语言](multilingual.md)。

```text
python -X utf8 -B scripts/offline_intake.py --output <新的外置绝对路径/开始填写资料.html>
```

导出会内嵌随包插画和本地资料包下载器，不联网、不预填私人资料；目标必须是新文件。先填写城市／区县和国家／省份，下载的原请求允许`birthplace`与`cast_place`待解析，`agent_report run`会在分析前自动查询，不需要用户补坐标或时区。地理查询需联网，所用Open-Meteo/GeoNames来源及精度随任务保存；当前无密钥公共端点遵守其非商业使用条款，商业发行应先配置获得许可的服务方案。照片只随本地ZIP交接，不发送给地理查询服务。

页面的“下载资料包”和“重新下载资料包”都重新收集当前填写、实际互动、当前主题已选答题和已添加照片，生成新的ZIP；同一未关闭的填写页可以继续修改并多次下载，已下载的旧包保持原样。不把第一次生成的旧链接当作最新资料。正在打包或操作图片时避免重复提交，已开始但未完成的互动仍需完成或明确略过。在线一次性提交规则不变。照片容器、所属人员、摘要和未观察状态继续按原照片协议校验。
